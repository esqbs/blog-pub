# 域名层级结构

  1. 主机名.权威域名.顶级域名.根域名， 例如 tieba.baidu.com
  2. 根域名一般不写

# DNS解析过程

## 无缓存情况

		1.递归查询                         2.迭代查询 
用户电脑 -----------------> 本地DNS服务器 ------------------------------> 根域名服务器 .
		8.返回给客户端			|         3.返回顶级域名服务器记录
								|         4.迭代查询
								|--------------------------------------> 顶级域名服务器 .com .cn .org
								|         5.返回权威域名服务器记录
								|         6.迭代查询
								|--------------------------------------> 权威域名服务器 baidu.com
	                                      7.返回DNS记录
  1. 查询应用程序缓存
  2. 如果没有，则查询本地host，
  3. 如果没有，则查询本地DNS服务器 （ISP 互联网服务提供商），
  4. 如果没有，本地DNS服务器从根服务器查询顶级域名服务器的NS 记录和 A 记录 （IP地址）
  5. 本地DNS服务器从顶级域名服务器查询次级域名服务器的NS 记录和 A 记录（IP地址）
  6. 本地DNS服务器从权威域名服务器查询主机名的 IP 地址

递归查询和迭代查询

  • 递归查询指的是查询请求发出后，域名服务器代为向下一级域名服务器发出请求，最后向用户返回查询的最终结果。使用递归 查询，用户只需要发出一次查询请求
  • 迭代查询指的是查询请求后，域名服务器返回单次查询的结果。下一级的查询由用户自己请求。使用迭代查询，用户需要发出多次的查询请求

# 常见DNS记录类型

  • A记录（Address Record）：将域名指向一个IPv4地址。
  • AAAA记录（IPv6 Address Record）：将域名指向一个IPv6地址。
  • CNAME记录（Canonical Name Record）：将域名指向另一个域名（别名），常用于CDN服务或作为网站子域名的指向。
  • MX记录（Mail Exchanger Record）：指定接收电子邮件的邮件服务器及其优先级。
  • TXT记录（Text Record）：允许域名管理员添加任意文本到记录中，常用于验证域名所有权或提供其他信息，如SPF（发件人策略框架）记录。
  • NS记录（Name Server Record）：指定负责域名解析的服务器。
  • SOA记录（Start of Authority Record）：标识DNS区域（域）的权威名称服务器，并提供管理域的重要信息，如主DNS服务器的地址、域管理员的电子邮件地址等。
  • PTR记录（Pointer Record）：用于反向DNS查询，将IP地址映射回相应的域名。
  • SRV记录（Service Record）：用于指定提供特定服务的服务器及其端口。
  • CAA记录（Certification Authority Authorization）：用于指定哪些证书颁发机构（CA）被允许为该域名颁发证书。
  • TLSA记录（TLSA Record）：用于DNS-Based Authentication of Named Entities (DANE)，为TLS服务提供加密证书的校验信息。

# DNS缓存

在一个请求链中，当某个 DNS 服务器接收到一个 DNS 回答后，它能够将回答中的信息缓存在本地存储器中

# DNS请求协议格式

固定12字节首部 + 可变部分 
                  | 问题部分 Question
				  | 回答部分 Answer
				  | 授权部分 Authority
				  | 附加部分 Additional

# 固定12字节首部

字段 长度 描述
ID（标识） 16位 客户端设置的随机标识符，服务器在响应中返回相同值，用于匹配查询与响应。
Flags（标志） 16位 包含多个标志位，控制报文类型和查询方式，下文详述。
QDCOUNT 16位 问题部分（Question）中的记录数，通常为。
ANCOUNT 16位 回答部分（Answer）中的资源记录数。
NSCOUNT 16位 授权部分（Authority）中的资源记录数。
ARCOUNT 16位 附加部分（Additional）中的资源记录数

Flags（标志）

标志位 长度 描述
QR（查询/响应） 1位 0：表示查询报文；1：表示响应报文。
Opcode（操作码） 4位 指定查询类型：0：标准查询；1：反向查询；2：服务器状态请求。
AA（权威应答） 1位 仅响应报文有效。1：表示服务器是查询域名的权威服务器；0：表示不是。
TC（截断） 1位 1：表示响应报文因超过512字节而被截断，只返回前512字节。客户端需改用TCP重试。
RD（期望递归） 1位 1：客户端希望服务器执行递归查询；0：希望执行迭代查询。
RA（可用递归） 1位 仅响应报文有效。1：表示服务器支持递归查询。
Z（保留） 3位 保留字段，必须为0。
RCODE（返回码） 4位 仅响应报文有效，表示响应状态：0：无错误；1：格式错误；2：服务器失败；3：域名不存在；4：查询类型不支持；5：拒绝。

# 问题部分（Question）

字段 长度 描述
QNAME（查询名） 可变 要查询的域名，采用标签序列编码。例如，www.example.com编码为3www7example3com0。
QTYPE（查询类型） 16位 指定查询的资源记录类型。常见类型：A (IPv4地址)、AAAA (IPv6地址)、CNAME (别名)、MX (邮件交换)。
QCLASS（查询类） 16位 通常为IN (Internet)，值为1

# 资源记录部分（回答、授权、附加）

字段 长度 描述
NAME（域名） 可变 资源记录对应的域名，格式与QNAME相同，可能使用指针进行压缩。
TYPE（类型） 16位 资源记录的类型，与QTYPE含义相同。
CLASS（类） 16位 通常为IN (Internet)。
TTL（生存时间） 32位 该记录可被缓存的秒数。
RDLENGTH（数据长度） 16位 指明RDATA字段的字节长度。
RDATA（资源数据） 可变 记录的具体数据，其格式由TYPE字段决定。

# Window nslookup

# 默认查询（查 A 记录 / IPv4 地址）
nslookup www.baidu.com
# 指定 DNS 服务器查询
nslookup www.baidu.com 8.8.8.8
# 查询 CNAME 记录
nslookup -type=cname www.bilibili.com
# 查询 MX 记录（邮件交换记录，找邮件服务器）
nslookup -type=mx qq.com
# 查询 NS 记录（域名服务器记录，看这个域名交给谁管理）
nslookup -type=ns example.com
# 查询 TXT 记录（常用于域名所有权验证、SPF防垃圾邮件）
nslookup -type=txt example.com
#  查询 AAAA 记录（IPv6 地址）
nslookup -type=aaaa www.taobao.com
# 查询所有可用记录, 出于安全考虑，现在很多权威 DNS 服务器会拒绝返回 `any` 类型的请求
nslookup -type=any example.com
