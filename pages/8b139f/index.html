06.DNS

  • 域名层级结构
    • 主机名.权威域名.顶级域名.根域名
  • DNS解析过程
    • 查询应用程序缓存，如果没有
    • 则查询本地host， 如果没有
    • 则查询本地DNS服务器 （ISP 互联网服务提供商）， 如果没有
    • 本地DNS服务器从根服务器查询顶级域名服务器的NS 记录和 A 记录 （IP地址）
    • 本地DNS服务器从顶级域名服务器查询次级域名服务器的NS 记录和 A 记录（IP地址）
    • 本地DNS服务器从权威域名服务器查询主机名的 IP 地址
  • 常见DNS记录类型 dns 域名服务器 | Node.js v23 文档 (opens new window)
    • A记录（Address Record）：将域名指向一个IPv4地址。
    • AAAA记录（IPv6 Address Record）：将域名指向一个IPv6地址。
    • CNAME记录（Canonical Name Record）：将域名指向另一个域名（别名），常用于CDN服务或作为网站子域名的指向。
    • MX记录（Mail Exchanger Record）：指定接收电子邮件的邮件服务器及其优先级。
    • TXT记录（Text Record）：允许域名管理员添加任意文本到记录中，常用于验证域名所有权或提供其他信息，如SPF（发件人策略框架）记录。
    • NS记录（Name Server Record）：指定负责域名解析的服务器。
    • SOA记录（Start of Authority Record）：标识DNS区域（域）的权威名称服务器，并提供管理域的重要信息，如主DNS服务器的地址、域管理员的电子邮件地址等。
    • PTR记录（Pointer Record）：用于反向DNS查询，将IP地址映射回相应的域名。
    • SRV记录（Service Record）：用于指定提供特定服务的服务器及其端口。
    • CAA记录（Certification Authority Authorization）：用于指定哪些证书颁发机构（CA）被允许为该域名颁发证书。
    • TLSA记录（TLSA Record）：用于DNS-Based Authentication of Named Entities (DANE)，为TLS服务提供加密证书的校验信息。
  • 递归查询和迭代查询
    • 递归查询指的是查询请求发出后，域名服务器代为向下一级域名服务器发出请求，最后向用户返回查询的最终结果。使用递归 查询，用户只需要发出一次查询请求
    • 迭代查询指的是查询请求后，域名服务器返回单次查询的结果。下一级的查询由用户自己请求。使用迭代查询，用户需要发出 多次的查询请求
  • DNS缓存
    • 在一个请求链中，当某个 DNS 服务器接收到一个 DNS 回答后，它能够将回答中的信息缓存在本地存储器中
  • DNS 实现负载平衡
    • DNS 可以用于在冗余的服务器上实现负载平衡。因为现在一般的大型网站使用多台服务器提供服务，因此一个域名可能会对应多个服务器地址。当用户向网域名请求的时候，DNS 服务器返回这个域名所对应的服务器 IP 地址的集合，但在每个回答中，会循环这些 IP 地址的顺序，用户一般会选择排在前面的地址发送请求。以此将用户的请求均衡的分配到各个不同的服务器上，这样来实现负载均衡。这种方式有一个缺点就是，由于 DNS 服务器中存在缓存，所以有可能一个服务器出现故障后，域名解析仍然返回的是那个 IP 地址，就会造成访问的问题。
    • 实现方式：
      • 简单轮询（Round Robin）
        • 这是最基础的负载均衡方法，DNS服务器会按顺序返回不同的IP地址列表，每次查询时轮流提供不同的地址。
      • 加权轮询（Weighted Round Robin）
        • 在这种方法中，不同的服务器可以有不同的权重，权重高的服务器会被更频繁地返回给用户。
      • 地理感知负载均衡
        • DNS服务器可以根据请求发起的地理位置，返回最近或最佳的服务器IP地址。
      • 故障转移（Failover）
        • 如果某个服务器发生故障，DNS负载均衡器会自动停止向该服务器发送流量，并将流量重定向到健康的服务器。
      • 延迟感知路由
        • DNS服务器可以根据网络延迟和服务器负载来选择最佳的服务器IP地址。
      • 全局负载均衡服务（GLBS）
        • 一些云服务提供商提供全局负载均衡服务，这些服务可以自动管理DNS记录，并根据实时性能数据来优化流量分配。
