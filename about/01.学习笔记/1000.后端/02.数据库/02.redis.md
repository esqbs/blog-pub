# Redis

## 一、Redis

> Redis是一个用c语言开发的、基于内存结构进行键值对存储的、高性能的、非关系型数据库

### 应用场景

* 缓存：为提高数据访问速度、降低数据库访问压力
* 点赞、排行榜、计时器等功能：对数据实时读写要求比较高
* 分布式锁
* 分布式会话：在分布式系统中实现session（共享缓存）
* 消息中间件

### 优缺点

1. 优点
   * 基于内存结构，性能极高
   * 基于键值对，支持多种类型
   * 所有操作都具有原子性，可通过lua脚本将多个操作合并为一个原子操作
   * 基于单线程，但其多路复用实现了高性能读写
2. 缺点
   * 缓存数据与数据库必须通过两次写操作才能保持数据一致
   * 使用缓存会导致缓存穿透、缓存击穿及缓存雪崩等问题
   * 进行持久存储存在丢失数据风险

```shell
# 设置最大并发数量
maxclients 10000
# 设置客户端和redis建立连接的最大空闲时间，设置为0表示无限制
```

## 四、持久化

> Redis提供了两种持久化策略：
>
> * RDB（Redis DataBase）
> * AOF（Append Only File）

### RDB

> RDB是redis默认的持久化策略，当redis中的写操作达到指定的次数、同时距离上一次持久化达到指定的时间就会将redis内存中的数据生成数据快照，保存到指定的rdb文件中

```shell
# rdb持久化开关
rdbcompression yes
# 指定rdb数据存储的文件
dbfilename dump.rdb
# 配置redis持久化策略
save 3600 1 300 100 60 10000
```

* 存在数据丢失风险
* 采用数据快照，不适合实时性持久化
* 数据量较小时，执行速度比较快
* 可以通过拷贝rdb文件轻松实现数据移植

### AOF

> 当达到设定触发条件时，将redis执行的写操作指令存储在aof文件中，默认未开启

```shell
# 是否开启AOF 
appendonly no
# 设置触发条件
appendsync always		# 只要执行成功的写操作，就执行aof
appendsync evetysec		# 每秒进行一次aof
appendsync no			# 让redis执行决定aof

# 设置aof文件路径
appendfilename "appendonly.aof"
appenddirname "appendonlydir"
```

* aof文件也可以通过拷贝aof文件进行数据移植
*  aof存储指令，而且会对指令进行整理；RDB直接存储快照，数据量不大时，RDB较快
* aof对指令文件进行增量更新，更适合实时性持久化
* 同时存在aof和rdb时，aof优先

## 六、缓存穿透、缓存击穿、缓存雪崩

### 缓存击穿

> 缓存击穿：大量的并发请求同时访问redis中不存在的数据，导致大量请求同时访问数据库

* 使用双重检测锁解决

  ```java
      @Override
      public ResultVO ListIndexImg() {
          try {
              String imgStr = stringRedisTemplate.boundValueOps("indexImg").get();
              if(imgStr != null) {
                  JavaType indexImgJavaType = objectMapper.getTypeFactory().constructParametricType(ArrayList.class, IndexImg.class);
                  List<IndexImg> indexImgs = objectMapper.readValue(imgStr, indexImgJavaType);
                  return new ResultVO(ResStatus.OK, "success", indexImgs);
              } else {
                  // 第二次检查redis中是否存在
                  synchronized (this) {
                      String s = stringRedisTemplate.boundValueOps("indexImg").get();
                      if(s == null) {
                          List<IndexImg> indexImgs = indexImgMapper.listIndexImg();
                          System.out.println("请求数据库-------------");
                          if(indexImgs.size() > 0) {
                              stringRedisTemplate.boundValueOps("indexImg").set(objectMapper.writeValueAsString(indexImgs));
                              stringRedisTemplate.boundValueOps("indexImg").expire(1, TimeUnit.DAYS);
                              return new ResultVO(ResStatus.OK, "success", indexImgs);
                          } else {
                              return new ResultVO(ResStatus.NO, "fail", null);
                          }
                      } else {
                          JavaType indexImgJavaType = objectMapper.getTypeFactory().constructParametricType(ArrayList.class, IndexImg.class);
                          List<IndexImg> indexImgs = objectMapper.readValue(s, indexImgJavaType);
                          return new ResultVO(ResStatus.OK, "success", indexImgs);
                      }
                  }
              }
          } catch (JsonProcessingException e) {
              e.printStackTrace();
          }
          return new ResultVO(ResStatus.NO, "fail", null);
      }
  }
  ```

### 缓存穿透

> 缓存穿透：大量的并发请求同时访问redis和数据库中不存在的数据，导致大量请求同时访问数据库

* 解决方案：设置一个非空数据到redis， 并设置过期时间（10s左右）

### 缓存雪崩

> 缓存雪崩：redis中的数据集中过期，导致大量请求同时访问数据库

* 将缓存中的数据设置为不同的过期时间
* 在访问洪峰到达前缓存热点数据，过期时间设置到流量最低的时段

## 七、主从复制

> 在多个redis实例建立主从关系，当主redis中的数据发生变化时，从redis中的数据也会同步发生变化
>
> * 主从配置可以实现redis数据的备份，保证数据安全性
> * 主从配置可以实现redis的读写分离

```shell

# 拷贝redis.conf到msconf文件夹

vim redis-master.conf

protected-mode no
port 6080 
pidfile /var/run/redis_6380.pid
dbfilename dump_6380.rdb

# 复制redis-slave1.conf redis-slave2.conf

redis-server redis-slave2.conf
```

## 十、redis淘汰策略

```shell
# redis.conf
# volatile-lru -> 从设置了过期时间的数据中淘汰最久未使用的数据
# allkeys-lru -> 从所有数据中淘汰最久未使用的数据
# volatile-lfu -> 从设置了过期时间的数据中淘汰最少未使用的数据
# allkeys-lfu -> 从所有数据中淘汰最少未使用的数据

# volatile-ttl -> 淘汰固过期时间最短的数据
# noeviction -> 不淘汰任何数据，当内存不够时直接抛出异常
```

## 十一、分布式会话

> 集群或分布式系统本质都是多个系统，假设这个里有两个服务器节点，分别是AB系统，他们可以是集群，也可以是分布式系统，一开始用户和A系统交互，那么这个时候的用户状态，我们可以保存到redis中，作为A系统的会话信息，随后用户的请求进入到了B系统，那么B系统中的会话我也同样和redis关联，如此AB系统的sessi on就统一了。当然cookie是会随着用户的访问携带过来的。那么这个其实就是分布式会话，通过redis来保存用户的状态。

```java
@Configuration
public class RedissonConfig {

    @Value("${redisson.addr.singleAddr.host}")
    private String host;

    @Value("${redisson.addr.singleAddr.password}")
    private String password;

    @Value("${redisson.addr.singleAddr.database}")
    private int database;

    @Bean
    public RedissonClient redissonClient() {
        Config config = new Config();
        config.useSingleServer()
                .setAddress(host)
                .setPassword(password)
                .setDatabase(database);
        return Redisson.create(config);
    }
}
```

```java
        // 记录加锁的skuid
        ArrayList<String> skuids = new ArrayList<>();
        // 记录本线程加锁UUID, 释放时只能释放自己的锁
        HashMap<String, RLock> lockMap = new HashMap<>();
        for (ShoppingCartVO shoppingCartVO : shoppingCartVOList) {
            int skuId = shoppingCartVO.getSkuId();
            RLock lock = redissonClient.getLock(String.valueOf(skuId));
            Boolean ifAbsent = null;
            try {
                ifAbsent = lock.tryLock(10, 3, TimeUnit.SECONDS);
                if (ifAbsent) {
                    lockMap.put(String.valueOf(skuId), lock);
                    skuids.add(String.valueOf(skuId));
                }
            } catch (InterruptedException e) {
                e.printStackTrace();
            }

            isLock = isLock && ifAbsent;
        }

        try {
            if (isLock) {
                shoppingCartVOList = shopingCartMapper.selectShoppingCartByIds(cids);
                if (shoppingCartVOList.size() == 0) {
                    return new ResultVO(ResStatus.NO, "未查询到购物车信息", null);
                }

                // 1. 校验库存
                boolean flag = true;
                StringBuilder untitled = new StringBuilder();
                for (ShoppingCartVO sc : shoppingCartVOList) {
                    if (sc.getCartNum() > sc.getStock()) {
                        flag = false;
                    }
                    untitled.append(sc.getProductName()).append(",");
                }

                if (flag) {
                    // 2. 保存订单
                    orders.setUntitled(untitled.toString());
                    orders.setCreateTime(new Date());
                    orders.setStatus((byte) 1);

                    String orderNum = UUID.randomUUID().toString().replace("-", "");
                    orders.setId(orderNum);

                    int i = ordersMapper.insert(orders);

                    if (i > 0) {
                        // 3. 生成商品快照
                        List<OrderItem> orderItemList = new ArrayList<>();
                        for (ShoppingCartVO sc : shoppingCartVOList) {
                            OrderItem orderItem = new OrderItem();
                            orderItem.setOrderId(orderNum);
                            orderItem.setProductId(sc.getProductId());
                            orderItem.setProductName(sc.getProductName());
                            orderItem.setProductImg(sc.getProductImg());
                            orderItem.setSkuId(sc.getSkuId());
                            orderItem.setBuyCounts(sc.getCartNum());
                            orderItem.setTotalAmount(sc.getProductPrice() * sc.getCartNum());
                            orderItem.setBasketTime(sc.getCartTime());
                            orderItem.setBuyTime(new Date());
                            orderItem.setIsComment((byte) 0);
                            orderItemList.add(orderItem);
                        }
                        int j = orderItemMapper.insertList(orderItemList);

                        // 4. 扣减库存
                        for (ShoppingCartVO sc : shoppingCartVOList) {
                            int skuId = sc.getSkuId();
                            int newStock = sc.getStock() - sc.getCartNum();

                            Example example = new Example(ProductSku.class);
                            Example.Criteria criteria = example.createCriteria();
                            criteria.andEqualTo("id", skuId);


                            ProductSku productSku = new ProductSku();
                            productSku.setStock(newStock);
                            int k = productSkuMapper.updateByExampleSelective(productSku, example);
                        }

                        // 5. 删除购物车
                        for (int cid : cids) {
                            shopingCartMapper.deleteByPrimaryKey(cid);
                        }

                        return new ResultVO(ResStatus.OK, "提交成功", null);
                    }

                } else {
                    return new ResultVO(ResStatus.NO, "库存不足", null);
                }
            } else {
                return null;
            }
        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            // 释放锁
            for (String skuid : skuids) {
                lockMap.get(skuid).unlock();
            }
        }
        return new ResultVO(ResStatus.NO, "提交失败，请重试", null);
    }
```

```java
@Configuration
public class RedissonConfig {

    @Value("${redisson.addr.cluster.host}")
    private String host;

    @Value("${redisson.addr.cluster.password}")
    private String password;

    @Bean
    public RedissonClient redissonClient() {
        Config config = new Config();
       config.useClusterServers()
                .addNodeAddress(host.split(","))
```

```java
@Configuration
public class RedissonConfig {

    @Value("${redisson.addr.masterAndSlave.password}")
```

 ### redisson分布式锁特点

1. 互斥性

   分布式锁需要保证在不同的节点的不同线程的互斥

2. 可重用性

   同一个节点的同一个线程获取锁之后可再次获取这个锁

3. 锁超时

   加锁成功后设置超时时间，防止死锁

4. 高效可用

   加锁和解锁需要高效，同时保证高可用防止分布式锁失效

5. 支持阻塞和非阻塞

   支持lock和trylock

### 锁的分类

1. 乐观锁和悲观锁
2. 可重入锁和非可重入锁
3. 公平锁和非公平锁
4. 阻塞锁和非阻塞锁

### redisson的使用

```java
// 获取锁
// 获取非公平锁
RLock lock = redissonClient.getLock(skuId);
// 获取公平锁
RLock lock = redissonClient.getFairLock(skuId);

// 加锁
// 阻塞锁
lock.lock(10, TimeUnit.SECONDS);
// 非阻塞锁
boolean ifAbsent = lock.tryLock(10, 3, TimeUnit.SECONDS);

// 释放锁
lock.unlock()
```
