# C++插件

- C++插件（.node）
	- 说明
		- 本质编译为各个系统的动态连接库
		- 上下文可感知（在多个上下文中多次加载 Node.js 插件）
	- 开发方式
		- 直接使用内部 V8、libuv 和 Node.js 库（需要考虑v8、node.js版本）
		- [nan]([nodejs/nan: Native Abstractions for Node.js](https://github.com/nodejs/nan))（提供了兼容v8、node.js版本的宏）
		- Node-API （推荐）
			- C++ 风格的N-API[nodejs/node-addon-api: Module for using Node-API from C++](https://github.com/nodejs/node-addon-api)
			- `#define NAPI_VERSION 3`使用对应版本的N-API
			- `#define NAPI_EXPERIMENTAL` 使用当前版本的实验功能
			- `#define NODE_API_EXPERIMENTAL_<FEATURE_NAME>_OPT_OUT`禁用实验功能
			- 语法
				- 模块注册
					- `NAPI_MODULE(NODE_GYP_MODULE_NAME, Init)`
					- `napi_value Init(napi_env env, napi_value exports) { return exports};` exports默认是一个空对象
				- 环境生命周期
					- `napi_set_instance_data`将 data 与当前运行的 Node.js 环境相关联（即上下文可感知）
					- `napi_get_instance_data`检索与当前Node.js环境关联的数据，如果没有设置，返回NULL
				- 错误处理
					- 所有 API 函数的返回类型都是 napi_status
					- 在返回 `napi_ok` 或 `napi_pending_exception` 以外的返回值的情况下， 必须调用 `napi_is_exception_pending` 来检查是否有异常挂起
					- `napi_get_and_clear_last_exception`返回一个未决的异常，没有返回 NULL
					- `napi_get_last_error_info` 返回包含有关错误的更多信息的 `napi_extended_error_info` 结构
					- 抛出异常
						- `napi_throw`
						- `napi_throw_error`
						- `napi_throw_type_error`
						- `napi_throw_range_error`
						- `node_api_throw_syntax_error`
						- `napi_is_error`
					- 创建Error
						- `napi_create_error`
						- `napi_create_type_error`
						- `napi_create_range_error`
						- `node_api_create_syntax_error`
					- `napi_fatal_exception`在 JavaScript 中触发 'uncaughtException'，如果异步回调抛出无法恢复的异常，则很有用
					- `napi_fatal_error` 致命错误，进程将终止
				- 生命周期管理
					- 普通句柄的生命周期由作用域管理
					- 使句柄生命周期短于作用域
						- `napi_open_handle_scope`和`napi_close_handle_scope`该范围关联的任何句柄都将失效
						- `napi_open_escapable_handle_scope`和`napi_close_escapable_handle_scope`，作用同上`napi_escape_handle`使某个句柄的生命周期在前面的范围外有效
					- 创建对值的持久引用
						- `napi_create_reference`创建应用
						- `napi_reference_ref`引用计数加一
						- `napi_reference_unref`引用计数减一
						- `napi_delete_reference`删除引用
						- `napi_get_reference_value`与应用关联的值，没有返回NULL
					- 当前 Node.js 环境退出时的清理
						- `napi_add_env_cleanup_hook`和`napi_remove_env_cleanup_hook`
						- `napi_add_async_cleanup_hook` 和`napi_remove_async_cleanup_hook`
					- 在 Node.js 环境退出时完成
						- `napi_finalize` 回调的调用安排在手动注册的清理钩子之后

					- `napi_define_class`定义一个类，

				- 异步
					- `napi_create_async_work`创建一个异步work, 参数包含执行和完成的回调，执行回调在工作线程池运行，不在主线程，相当于worker
					- `napi_delete_async_work`删除work
					- `napi_queue_async_work`排队等候执行
					- `napi_cancel_async_work`如果尚未启动，会取消排队的工作

	- 构建工具
		- node-gyp
			- 命令
				- `$ node-gyp configure`：通过当前目录的 binding.gyp 生成项目文件，如 Makefile 等
				- `$ node-gyp build`：将当前项目进行构建编译，前置操作必须先 configure
				- `$ node-gyp clean`：清理生成的构建文件以及输出目录，说白了就是把目录清理了
				- `$ node-gyp rebuild`：相当于依次执行了 clean、configure 和 build
				- `$ node-gyp install`：手动下载当前版本的 Node.js 的头文件和库文件到对应目录
			- 编译时能添加当前node版本的头文件和动态连接文件
