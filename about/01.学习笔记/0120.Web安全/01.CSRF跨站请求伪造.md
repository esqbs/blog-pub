# CSRF跨站请求伪造

- 介绍
    - 受害者登录[a.com](http://a.com) 并保留凭证（Cookie）
    - 攻击者引诱受害者访问[b.com](http://b.com)
    - [b.com](http://b.com)向[a.com](http://a.com)发送了请求，浏览器默认携带了[a.com](http://a.com)的Cookie
- 攻击类型
    - GET类型
        - 如一个包含img的页面
    - POST类型
        - 如一个包含表单的页面
    - 链接类型
        - 引诱点击链接
- 特点
    - 攻击一般发起在第三方网站
    - 攻击只是冒用，不能窃取登录凭证（Cookie）
    - 跨站请求可以使用各种方式：图片URL、超链接、Form表单提交等
- 防护策略
    - 阻止不明外域访问
        - 同源检测
            - origin header
                - 以下两种情况不存在origin
                    - IE11同源策略： IE 11 不会在跨站CORS请求上添加Origin标头，Referer头将仍然是唯一的标识
                    - 302重定向：在302重定向之后Origin不包含在重定向的请求中
            - referer header
                - 对于Ajax请求，图片和script等资源请求，Referer为发起请求的页面地址
                - 对于页面跳转，Referer为打开页面历史记录的前一个页面地址
                - 最新的Referer策略：[https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Headers/Referrer-Policy](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Headers/Referrer-Policy)
                - 以下情况Referer没有或不可信
                    - IE6、7下使用window.location.href=url进行界面的跳转，会丢失Referer
                    - IE6、7下使用window.open，也会缺失Referer
                    - HTTPS页面跳转到HTTP页面，所有浏览器Referer都丢失
                    - 点击Flash上到达另外一个网站的时候，Referer的情况就比较杂乱，不太可信
            - 无法确认来源域名
                - 建议直接进行阻止
            - 被搜索引擎爬取的链接页面，应取消同源检测
        - Samesite Cookie
            - Samesite=Strict： Cookie 在任何情况下都不可能作为第三方 Cookie
            - Samesite=Lax： 假如这个请求是这种请求（改变了当前页面或者打开了新页面）且同时是个GET请求，则这个Cookie可以作为第三方Cookie
            - SamesiteCookie目前不支持子域
    - 提交时要求附加本域才能获取信息
        - CSRF Token
            - 原理
                - 将CSRF Token输出到页面
                - 提交表单时携带上Token
                - 服务器验证Token
            - 采用Encrypted Token Pattern方式
                - 使用UserID、时间戳和随机数，通过加密的方法生成，不需要在服务端存储Token
        - 双重Cookie验证
            - 原理
                - 服务端生成一个Cookie, 内容为随机值
                - 客户端读取Cookie，将其作为表单项提交
                - 服务端验证Cookie和表单中的Cookie
            - 缺点
                - 如果有其他XSS攻击可以修改Cookie, 防御失效
                - 难以做到子域名隔离
                    - 如果某个子域受到攻击，Cookie被修改，其他域防御失效
- 其他攻击方式和措施
    - 攻击方式
        - 文件上传漏洞
            - 攻击者将HTML、JSON等类型文件伪装成图片上传
            - img标签应用
            - 浏览器资源嗅探发现类型为HTML，将其解析执行
        - 评论功能
            - 恶意网址被添加到评论
    - 防护
        - 严格管理上传接口，防止预期之外的上传内容
        - 添加 X-Content-Type-Options: nosniff 禁止浏览器资源嗅探
        - 上传图片时，进行校验和转存
        - 当用户打开其他用户填写的链接时，告知风险
- 测试和监控
    - 测试工具：CSRFTester
    - 监控
